# Exactification of the stripped RX-Hall model

9 September 2026. Research direction: Paul Lenz. Mathematical development and internal checking: ChatGPT/Geeps.

**Status: proof-producing finite-model checkpoint, still conditional on the universal graph-to-RX-Hall bridge. This is not an unrestricted Murty-Simon theorem and is not external review.**

## 1. Purpose

The first RX-Hall checkpoint used floating-point HiGHS only as a reconnaissance oracle. That was intentionally not accepted as proof evidence. The next step is to make every finite-model exclusion checkable by exact integer arithmetic.

`rx_hall_exact.py` rebuilds the stripped RX-Hall necessary-condition model from the same graph-derived demand/residual data and accepts a contradiction only after an integer Farkas certificate has been checked directly against the integer coefficient dictionaries.

The floating solver may propose a dual ray. It cannot certify the result by itself.

## 2. Elementary unit-density bounds

The original reconnaissance scanner leaves every LP variable merely nonnegative. For exact certificate recovery we make explicit the additional bounds

```text
0 <= x <= 1
```

for every grouped fraction/density variable `W`, `P`, `L`, and `Z`.

These are valid necessary conditions for every actual graph image:

- `W` is a fraction of source vertices in one residual-degree group;
- `L` is a fraction of labels in one demand group;
- `P` is a density of selected oriented source/supplement pairs between two actual vertex groups;
- `Z` is a density of selected source/label incidences between two actual groups.

Thus every individual variable is at most one.

This does **not** restore the old unordered-pair aggregate capacity constraint. In particular, the exact RX-Hall relaxation does not require the sum of multiple `P` type variables representing the two orientations or different source-type decompositions of one grouped pair to satisfy the old pair-capacity inequality. The model remains deliberately weaker than the old final endpoint model.

The unit bounds serve a second technical purpose. When a floating dual proposal is scaled and rounded to integer weights, tiny negative residual coefficients may remain. The exact checker may add the corresponding valid `x<=1` row with precisely the integer multiplier required to bring that coefficient to zero. The final accepted certificate therefore consists entirely of exact nonnegative combinations of genuine model inequalities plus arbitrary integer combinations of equalities.

## 3. Exact Farkas acceptance rule

Write the model as

```text
A x <= b,
E x  = f,
x >= 0.
```

A certificate consists of integer multipliers

```text
lambda >= 0,
mu arbitrary,
```

such that

```text
lambda A + mu E >= 0             coordinatewise,
lambda b + mu f < 0.
```

For any feasible nonnegative `x`, the first relation would give

```text
0 <= (lambda A + mu E)x <= lambda b + mu f < 0,
```

a contradiction.

`verify_certificate()` recomputes every coefficient and right-hand side using Python integers. It checks row indices, multiplier signs, nonnegative combined variable coefficients, exact agreement with the stored right-hand side, and strict negativity. No numerical tolerance occurs in certificate acceptance.

## 4. Pilot on the six red numerical states

GitHub Actions run `34295699108` contained six states on which the default HiGHS route returned public SciPy status 4 rather than a standard infeasibility status. Those six were independently rebuilt and retried by HiGHS-IPM, which returned numerical infeasibility in every case; see `NUMERICAL_STATUS4_DIAGNOSIS.md`.

The exact RX-Hall layer was then tested on precisely those six cases. Every one admits an integer Farkas contradiction verified by the exact checker.

This is a useful adversarial pilot because these are the states for which the ordinary numerical route was least well behaved. It is not yet a completeness claim for all n=29 hard rows until the sharded exact workflow has finished successfully.

## 6. What a successful replay would mean

If all 996 rows receive exact verified Farkas contradictions, the conclusion is:

> Within the audited universal graph-to-demand/RX-Hall bridge and after the earlier exact charging/threshold preparation that defines these frontiers, the stripped RX-Hall relaxation itself excludes every positive-demand zero-slack n=29 Delta=16 frontier row using exact arithmetic.

This would strengthen the evidence that cumulative selected-degree tails and the old unordered-pair aggregate-capacity machinery are not essential for these n=29 hard frontiers.

It would **not** prove that RX-Hall alone resolves every possible parameter triple, that the same finite elimination works for arbitrary n, or that the universal graph bridge is correct. Those remain mathematical obligations.

## 7. Next mathematical use

Once complete exact certificates exist, the highest-value next step is not another fixed-order computation. It is to classify and mine the dual weights by constraint family:

```text
source-type normalization,
source/supplement transport,
label normalization,
residual-column budget,
source-label Hall/incidence,
unit-density bounds.
```

Repeated dual patterns should then be translated into one or a small family of symbolic Hall/resource inequalities. That is the intended route toward eliminating the LP and attacking the remaining near-balanced maximum-degree band parametrically.
