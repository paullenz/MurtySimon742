## 6. Unit V — independent hand audit of the support-block package

The principal new hand steps in `FIRST_STRICT_FUNNEL_RESERVOIR.md` were re-derived from the already-verified unique-hole funnel rather than accepted from the interrupted prose.

### 6.1 Type-R overlap collapse — verified

For Type-R heads `x,x'`, if `i in I_x cap I_x'`, the reverse funnel gives the same fixed graph set

`N(q_i) cap N(a_0)={z_x}={z_x'}`.

Hence `z_x=z_x'`. Outside-U localization gives `c(z_x)=bar c(x)` and `c(z_x')=bar c(x')`, so `c(x)=c(x')` and therefore `I_x=I_x'`.

No source-tuple injectivity is used. Distinct Type-R code classes therefore have pairwise disjoint nonempty agreement blocks.

### 6.2 Type-F blocks and global disjoint-block normal form — verified

A Type-F head has `I_x={i}` for one `i in S_0`. For binary tight codes, the agreement set with `d` determines the code. Thus two Type-F heads using the same singleton coordinate belong to the same code class. Distinct Type-F classes therefore use distinct coordinates of `S_0`.

Type-R blocks lie in `I_0`, Type-F blocks lie in `S_0`, and `S_0 dotcup I_0=[p]`. Hence the distinct buffer-neighbour code classes have pairwise disjoint nonempty blocks and

`sum_C |I_C| <= p`, `h<=p`.

The distance identities in Theorem 4.1 follow directly by symmetric difference of the agreement blocks.

Thus every head in that Type-R class uses the same physical selected witness. This is a graph-fixed singleton statement, not raw-witness uniqueness imported from the source-tuple theorem.

## 7. Unit VI — independent audit of the resource and rooted-slot bills
