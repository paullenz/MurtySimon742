\begin{abstract}
This companion specifies the immutable evidence, checking procedure and review boundaries for the direct order-28 candidate proof. It separates preservation checks, exact computational exclusion, mathematical validity and external review. The reviewer entry point checks the six original component archives, enforces a mandatory guarded version of the v8 residual enumerator in a derivative working copy, replays both edge-count scopes, and checks five stage handoffs. The original sources, evidence, timing reports and manifests are not rewritten. The new entry point performs full checking by default; integrity-only operation must be explicitly requested. This is a reproducibility and review document, not an independent endorsement of the theorem.
\end{abstract}

\section{What is being reviewed}
The companion manuscript, \emph{The Murty--Simon bound at order 28: a computer-assisted candidate proof}, proposes
\[
 e(G)\le196,\qquad e(G)=196\iff G\cong K_{14,14}
\]
for simple diameter-two edge-critical graphs of order 28. Infinite distance is allowed when deletion disconnects a graph. The direct route has two separate degree-15 calculations: $(a,b,t)=(12,15,1)$ at 196 edges and $(12,15,2)$ at 197 edges. Other maximum degrees and the regular equality boundary have explicit arguments. Fan's cited strict bound of $197.2075$ is the external input excluding 198 or more edges.

The direct route uses \textbf{LocalIncidence-v7}, whose final equality partition is $22+19+347$. It does not use the separate \textbf{degree-load-v7} route, whose partition is $173+215$ and which adds a weak-core density reduction. The latter's numerical bundle and that reduction are not required by this release. Alternative exclusions of the same row are not additional rows.

The frozen n=25 and n=27 candidates are separate papers. This release neither changes those editions nor promotes the governed theorem ledger. It creates an editorial and engineering layer over the direct n=28 evidence.

\section{Run the hardened checking release}
Use Python 3.10 or later with assertions enabled, a C++17 compiler invoked as \texttt{g++}, and Boost headers. No optimisation solver or network connection is used during checking. Installation of prerequisites is separate from the checking run. The original capsule recovery programs for v3/v4 were tested in CPython 3.13.5 and fail closed on incompatible byte reconstruction; obtaining the exact original ZIPs avoids that extra recovery dependency.

Place the six original ZIPs in one directory. From the reviewer release directory run:
\begin{Code}
python3 -I -B review_check.py \
  --archives-dir /absolute/path/to/original-zips \
  --output /absolute/path/to/new-review-run --jobs 3
\end{Code}
\textbf{This command performs full checking by default.} The output must not exist and must be outside the release directory. Every component writes to a new working copy or separate result directory. At most the requested number of component subprocesses run concurrently within this invocation. A failure produces a nonzero exit code and preserves the corresponding logs; it must not be treated as an exclusion.

For an explicit integrity-only pass:
\begin{Code}
python3 -I -B review_check.py \
  --archives-dir /absolute/path/to/original-zips \
  --output /absolute/path/to/new-integrity-run --verify-only
\end{Code}
That result says \texttt{arithmetic\_replayed: false}. It does not certify either density scope. Do not use \texttt{-O}, a smoke-test result, or a standalone helper's successful exit code as a substitute for the full command.

\section{The input-validation correction}
\subsection{The defect and why it is non-blocking for the original driver}
The committed internal audit's RT-01 finding concerns the standalone v8 \texttt{src/check\_rows.cpp}. It accepted an unsupported residual interval such as $64..64$ and could produce a successful empty report. Such an output is not an exclusion certificate.

The original \texttt{check197.py} reconstructs the exact initial domain and verifies $15\le r_{\min}\le r_{\max}\le63$ for every retained interval. It verifies the complete demand-input file before invoking the helper. Thus the audit's malformed input does not reach the helper through the admitted proof entry point. The recorded valid-domain calculation is not invalidated by that standalone weakness.

\subsection{The reviewer-release correction}
This release implements the documented guard correction as a new, versioned derivative, not as a silent edit of historical evidence. It does not claim that this new guard source is byte-identical to the earlier audit patch. It preloads and validates the entire helper input before opening outputs: positive bounded record count; all twelve demands in range; sorted demands; supported ordered intervals; strictly ordered, non-duplicate demand records; complete records; and no trailing data. It also rejects identical path strings and checks output write failures. These are operational input guards, not a claim of comprehensive security hardening against every filesystem adversary.

The enumeration, capacity refinement, arithmetic comparisons, row digest, survivor serialisation and per-demand band loops are unchanged. \texttt{OVERLAY.json} pins both source versions, and \texttt{check\_rows\_input\_guard.patch} shows the entire difference.

The release tests exercise 13 malformed cases: out-of-range and inverted intervals; negative, zero, excessive and unrepresentable counts; truncated input; negative and oversized demands; unsorted demands; duplicate records; and trailing data. Every such test must return nonzero before output creation. The valid-domain regression must match the original complete 8,216,928-row report, all survivor bytes and all per-demand band bytes.

The full reviewer driver applies the overlay automatically. A reviewer should not have to remember an optional patch step. Original source and original archives remain available for exact historical reproduction.

\section{Mathematical review versus numerical reproduction}
\subsection{The key logical implication}
Every hypothetical critical graph in the claimed scope must yield one of the enumerated records, and must lift to a feasible point of the necessary system attached to that record. Exact arithmetic only establishes that the system is impossible. An erroneous universal constraint could invalidate the graph-to-system implication even while all arithmetic certificates remain valid. This is the central reason for independent mathematical review.

The graph arguments needing particular attention are the uniqueness of quasi-edge exceptions; disjoint residual injections and their empty-set cases; the strict positive-surplus premise of residual activity; exclusion of isolated $H[A]$ vertices; the distinction $x_i\ge s_i$ rather than $x_i=s_i$; and source/supplement pair uniqueness across orientations. The endpoint bound $R_i+x_i\ge q_u+p_u$ must concern the same incidence and actual degree types.

For the finite reductions, inspect domain membership and independent counts; paired column options and exact slack; the preservation of actual witnesses under repeated matching and cap refinement; activation-cost normalisation by incoming capacities; and source-conditioned fixed totals. Symmetry classes are an averaging device, not assumed automorphisms. Distinct-endpoint corrections and class-size factors must be correct. Branches must split genuine integral graph counts, not raw fractional averages.

The source-local residual injection uses quasi-edges for missing pairs inside $A$. It is validly applied to the original critical graph in the direct route. It must not be imported without proof into a weaker object retaining only selected $B$-quasi-edges. That distinction separates this proof from the alternative weak-core route.

\subsection{Independence and regression limits}
The original discovery and checking programs were separately implemented, but by the same assistant. The additional audit arithmetic kernel uses a fresh integer accumulator and branch checker while reusing preserved model constructors. It is not a third independent derivation of the graph constraints.

The committed audit reports fresh tests on 107 labelled critical graphs and no tested key-lemma failure. Its sample has no positive-surplus graph. The original component tests also include actual-graph lifts, fractional symmetry averages and abstract incidence systems. None of these finite samples proves a universal structural lemma or supplies empirical evidence that all hypothetical dense graphs have been observed. Their purpose is to catch implementation and local-argument errors.

No blocking defect was found in the audited direct route. That is a recorded internal audit conclusion, not a guarantee that no defect exists. No independent referee endorsement, publication acceptance, novelty/priority determination, improved general coefficient or formal-kernel verification is asserted.

\section{How a reviewer can report a result}
The release includes \texttt{REVIEW\_REPORT\_TEMPLATE.md}. A computational reviewer should identify the exact repository commit, archive hashes, operating system, Python and compiler versions, command, exit code, fresh report hashes, and any deviation from the expected output. A successful local run should not be described as proof of the universal lemmas.

A mathematical reviewer should name the precise lemma, equation, domain reduction or lifting rule examined; record whether it is verified, requires clarification, or has a counterexample; and distinguish a presentation improvement from a substantive gap. For a proposed defect, a concrete graph, small abstract system, missing case, or invalid inference is more informative than a general confidence score. For a code issue, preserve minimal input, stderr, exact command and the expected versus observed behaviour.

External review statuses start as \texttt{OPEN}. They must be changed only on receipt of an actual assessment, not merely because an invitation was sent or an internal replay passed. The n=25/n=27 frozen editions and original n=28 archives are not silently rewritten in response to editorial corrections; later editions record their differences.
